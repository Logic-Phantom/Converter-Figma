> 요청받은 세 기능이 이 프로젝트(Java 11, Eclipse/Tomcat, eXBuilder6 e6-compiler 1.0.6190, 런타임 1.0.5542)에서 **실제로 가능한지**를

## 0. 결론 요약

|---|---|---|---|

## 1. Swagger / OpenAPI 스펙 연동 — DataSet & Submission 자동 바인딩

### 1.1 검토

- 입력 인터페이스: 모든 변환 엔드포인트에 `swagger=<OpenAPI/Swagger JSON URL 또는 서버 파일 경로>` 파라미터. eXBuilder 화면 `clx-src/design/convertApi.clx` (Figma 링크 + Swagger URL + 토큰 + QA 체크) → `/design/convertApi.do`. 업로드 변환(`jsonConvert.do`)은 두 번째 JSON 업로드(`openapi`/`swagger` 키가 있는 문서)를 스펙으로 인식.
- YAML 은 지원하지 않는다(라이브러리 추가 없이 JSON 만; springdoc `/v3/api-docs`, springfox `/v2/api-docs` 는 JSON).
- eXBuilder6 의 CLX 바인딩 문법은 문서가 없어 e6-compiler 의 모델 클래스(`CleoPackageImpl` 상수)에서 후보를 뽑아 **11가지 변형을 컴파일**해 확정했다(§0 표).
- eXBuilder 프로토콜과 REST DTO 의 불일치: 런타임은 응답이 `{"dsList":[...]}` (JSONDataView) 형식일 때만 자동 적재한다. REST 백엔드가 `{data:{list:[...]}}` 를 주면 자동 적재가 안 되므로, 스펙에서 **배열 경로**(`data.list`)를 읽어 `submit-done` 핸들러가 `DataSet.build(rows)` 로 직접 적재하는 어댑터를 JS 에 생성한다. 요청도 마찬가지로 GET 은 DataMap 이 쿼리로, POST/PUT 은 `mediatype="application/json"` 으로 보낸다(백엔드가 프로토콜 봉투를 기대하면 서버 쪽 조정 필요 — JS 상단 주석에 명시).

### 1.2 동작

```
Figma JSON ─▶ UI-IR ─▶ ApiBinder(OpenApiSpec, ApiLabelMatcher) ─▶ UI-IR + {region.dataId, column.name, field.name, api.submissions}
                                                                        │
              ClxGenerator: dataset 컬럼명=DTO 속성, cl:datamap + cl:datamapbind, cl:submission(requestdata/responsedata/submit-done), 버튼 click·body load·grid selection-change 리스너
              CompanionJsGenerator + EventScriptGenerator: onBtnSearchClick / onBtnResetClick / onBtnDeleteClick / onBodyLoad / onGrd1SelectionChange / onSubListSubmitDone …
```

| 단계 | 규칙 |
|---|---|
| 스펙 파싱 (`OpenApiSpec`) | `$ref` 해석(components/schemas, definitions), `allOf` 병합, `oneOf/anyOf` 첫 항목. 응답 봉투 해제: 배열이면 items, 객체면 깊이 3 안의 첫 객체배열(`data.list`), 아니면 `data`/`result` 같은 단일 객체 봉투 |
| operation 선택 (`ApiBinder`) | 그리드: 목록(배열 응답) GET/POST 중 헤더와 매칭되는 필드 수 ×10 + 화면명/제목 키워드 +3 + GET +1. 폼: 상세(단일 객체 GET) / 저장(POST·PUT·PATCH body) / 삭제(같은 자원 경로의 DELETE). 폼이 없고 그리드 제목행에 `삭제` 가 있으면 행 삭제 DELETE |
| 라벨 ↔ 속성 (`ApiLabelMatcher`) | ① 속성 description/title 이 라벨을 포함 90~100 ② `ColumnNames` 관례 코드(성명→NM) 와 속성 토큰 일치 70~100 ③ 한글 조각 → 영문 토큰표(120여 개: 등록일→reg/regdt/created…, 여부→yn/flag…) 전 조각 일치 55~99(속성 토큰 커버리지로 동점 해소: 등록일→`regDate` 가 `otherYearRegYn` 보다 우선) ④ 남은 라벨만 AI(provider 설정 시)에게 후보 목록 중 선택시키고 화이트리스트 검증 + 캐시(`generated/ai-cache/api-labels.json`) |
| 조회영역 | 목록 operation 의 query 파라미터/요청 body 를 필드 라벨과 매칭 → `dmSearch`. 기간(daterange) 은 `startDate/endDate`, `fromYmd/toYmd`, `bgngDt/endDt` 쌍을 찾아 `from,to` 로 바인딩. 페이징 파라미터(`pageNo/pageSize`)는 경고로 안내 |
| 트리거 | 조회영역·그리드 제목행 버튼 중 `조회/검색/찾기` → subList, `저장/등록/확인`(정확히 또는 5자 이하) → subSave, `삭제` → subDelete, `초기화` → DataMap.clear(). 긴 업무 버튼("성인건강보험카드 등록")은 트리거로 쓰지 않음. 그리드 제목행의 행추가/삭제/저장이 `udcComGridCudBtns` 로 묶이면 UDC 가 보내는 `save`/`delete` 이벤트에 리스너를 달고, 삭제는 `ignoreDefaultDeleteAction=true` 로 두어 서버 DELETE 후 재조회하게 한다 |
| 생성 CLX | `<cl:datamap id="dmSearch"><cl:datacolumnlist><cl:datacolumn name="budgetYear"/>…`, 컨트롤에 `<cl:datamapbind property="value" datacontrolid="dmSearch" columnname="budgetYear"/>`, `<cl:submission id="subList" action="/api/v1/health-cards" method="get"><cl:listener name="submit-done" handler="onSubListSubmitDone"/><cl:requestdata dataid="dmSearch"/><cl:responsedata dataid="dsList"/></cl:submission>`, `<body><cl:listener name="load" handler="onBodyLoad"/>` |
| 생성 JS | 사용한 런타임 API 는 `exbuilder/runtime/cleopatra.js` 에서 존재를 확인: `Submission.send/xhr`, `DataSet.build/getRowCount`, `DataMap.build/clear/getValue`, `Grid.getSelectedRow`, `Row.getValue`. 경로 파라미터(`/{cardNo}`)는 `replacePathParams()` 로 선택 행/DataMap 값 치환 |

### 1.3 검증 (`tools/harness/OpenApiHarness.java`, 샘플 `tools/harness/samples/health-card.*.json`)

12개 검사 모두 통과: OpenAPI 3.x/Swagger 2.0 파싱, 점수 규칙, 바인딩(컬럼 11/11, 필드 6/6, subList + subDelete), ClxValidator, DataSet 컬럼명=DTO, DataMap+datamapbind,
submission 속성, 리스너, JS 핸들러 전부 정의, **스펙 없이 변환하면 v2.0 과 동일**. 생성된 `api.clx/api.js` 는 e6-compiler **BUILD SUCCESS** 이며 컴파일 결과에 `toDataMap(app.lookup("dmSearch"), "budgetYear")`, `addRequestData/addResponseData`, `addEventListener("submit-done", …)` 가 있다.
규칙 경로 회귀(46 OK) 와 AI 경로(7/7) 는 변화 없음.

### 1.4 한계

- 라벨↔속성 매칭은 description 이 있을 때 정확하다. description 없는 영문 축약 속성(`otherYearRegYn`) 은 토큰표에 의존하므로 `/designAi/*` 로 AI 를 켜거나 스펙에 description 을 채우는 것이 확실하다.
- 생성 JS 는 문법(e6-compiler 통과)과 사용 API 의 존재만 확인했고 실제 백엔드 호출은 서버가 있어야 검증된다. 필수값 검사·메시지 처리·페이징 파라미터는 `TODO` 로 남겨 둔다.
- 화면 하나에 그리드가 여러 개면 `dsList2/subList2…` 로 각각 바인딩하되, 조회영역은 첫 그리드의 operation 에만 연결한다.

## 2. Figma Design Tokens → eXBuilder6 Theme (.less)

### 2.1 검토

- `GET /v1/files/:key/variables/local` 은 Figma **Enterprise 플랜의 정회원 + `file_variables:read` scope** 에서만 응답한다(그 외 403/400). 따라서 Variables 만 믿을 수 없고, 모든 플랜에서 오는 파일 JSON 의 `styles`(FILL/TEXT/EFFECT 스타일, 이 저장소의 저장 JSON 47개에 모두 존재)를 기본 원천으로 삼고 Variables 는 있으면 추가한다.
- Figma 의 auto-layout 간격/모서리 값은 노드마다 달라 토큰이 아니므로(디자이너가 Variables 로 정의한 값만 토큰) 추측 추출은 하지 않는다.
- eXBuilder6 테마는 LESS 이고 `settings.part.less` 의 전역 변수(`@default-font`, `@default-text-color`, `@focus-border-color`, `@selection-background` …)가 모든 컨트롤 less 에서 쓰인다. LESS 는 **같은 스코프에서 마지막 정의가 이기므로** `cleopatra-theme.less` 에 덮어쓰기 파일을 import 하면 컨트롤 less 를 손대지 않고 테마가 바뀐다. e6-compiler 가 테마 less 를 css 로 컴파일하므로 결과를 검증할 수 있다.

### 2.2 동작 (`figma/theme/FigmaThemeSync`, `/figma/theme/sync.do`)

1. `fromVariables`: 컬렉션/모드 해석, alias 추적, COLOR → `#rrggbb`/`rgba()`, FLOAT → `px`(OPACITY/FONT_WEIGHT scope 는 단위 없음), STRING → 따옴표. 기본 모드는 `@figma-brand-color-primary-500`, 다른 모드는 `@figma-…--dark`.
2. `fromStyles`: `styles` 맵의 각 스타일을 처음 사용하는 노드에서 값을 읽음 — FILL → `fills[0]` 색(불투명도 포함), TEXT → `style`(family/size/weight/lineHeight) 을 `font` 단축형 + size/weight/family/line-height 토큰, EFFECT → `box-shadow` 문자열.
3. `sync`: `clx-src/theme/figma/figma-tokens.part.less`(전체 토큰), `figma-theme.part.less`(전역 변수 ← 토큰 매핑, 매칭 안 되면 주석), `figma-tokens.json` 을 쓰고, `apply=true`(기본) 면 `cleopatra-theme.less` 의 `@import "settings.part.less";` 다음 줄에 `@import "figma/figma-theme.part.less";` 를 **한 번만** 추가한다.
4. 매핑 규칙: 토큰 이름 정규식(`FigmaThemeSync.DEFAULT_MAP`, 예: focus ← `*focus*` 또는 `primary/500`, text ← `text/primary` 또는 `gray-90`). `application.properties` 의 `figma.theme.map.<변수>=<정규식>` 으로 고객사 토큰 명명에 맞춘다.

### 2.3 검증 (`ThemeSyncHarness`)

저장 JSON(`2025-08-04_e69f5327.json`, 스타일 30개) + 샘플 Variables 응답(`tools/harness/samples/variables-local.sample.json`, alias·2모드·FLOAT·STRING 포함) → 7개 검사 통과
(스타일 토큰 색 ≥5·폰트 ≥3, Variables 16토큰·alias 해석 `#1369c5`·Dark 모드 접미사·`6px`·`"Pretendard"`, LESS 변수 수 일치, 전역 변수 매핑, import 1회·재실행 시 불변, apply=false 시 테마 파일 불변).
그 결과 프로젝트 사본을 e6-compiler 로 컴파일 → **BUILD SUCCESS**, `cleopatra-theme.css` 에 토큰 값 반영.

### 2.4 한계

- 전역 변수 매핑은 이름 규칙 추정이므로 첫 동기화 뒤 `figma-theme.part.less` 의 주석(`← gray/gray-90 = #…`)을 보고 `figma.theme.map.*` 로 확정하는 절차가 필요하다.
- 컨트롤별 세부 스타일(버튼 클래스 `btn-primary-01` 색 등)은 전역 변수가 아니라 `theme/controls/*.less` 에 있어 자동 매핑 대상이 아니다(토큰 변수는 생성되므로 퍼블리셔가 `@figma-…` 를 참조해 쓰면 된다).

## 3. 시각 QA — Figma 렌더링 vs CLX 화면 픽셀 비교

### 3.1 검토

- "Playwright + pixelmatch" 는 Node 도구다. 이 프로젝트는 Java/Tomcat 이고 개발 PC 에 Node 가 없을 수 있으므로(이 PC 도 없음) **Node 없이 동작하는 경로를 기본**으로 하고 Playwright 는 옵션(`figma.qa.renderer=playwright` → `npx playwright screenshot`)으로 두었다.
- CLX 는 브라우저가 직접 열 수 없다. e6-compiler 의 `--main <app>` 옵션이 `index.html` 스텁(런타임·UDC·테마·앱 JS 로드 후 `cpr.core.Platform.INSTANCE.lookup(app).createNewInstance().run()`)을 만든다는 것을 확인했고, `file://` 로는 런타임 XHR 이 막히므로 임시 폴더를 `127.0.0.1` 임시 포트로 서빙한다.
- 픽셀 비교는 pixelmatch 알고리즘(YIQ 색차 + 안티앨리어싱 판별)을 Java 로 그대로 옮겼다(라이브러리 추가 없음, `java.awt.image` 만 사용). 크기가 다르면 큰 캔버스에 흰색으로 채워 비교한다.
- Figma 원본 PNG 는 `/v1/images/:key?ids=&scale=1`(Tier 1, `file_content:read`) — CANVAS(페이지) 노드는 렌더 불가이므로 프레임 단위 변환(`node-id` 링크)에서 의미가 있다.

### 3.2 동작 (`figma/qa/*`, `qa=true` 또는 `/figma/qa/compare.do`)

```
생성 CLX/JS ─▶ ClxCompiler(임시 프로젝트: .project/.settings/env.json/udc/theme 복사 → e6-compiler --main) ─▶ out/index.html + runtime/
           ─▶ HeadlessBrowser(127.0.0.1 서버 + Chrome --headless=new --window-size=프레임크기 --virtual-time-budget --screenshot)  ─▶ clx.png
Figma /v1/images ─▶ figma.png                                                     ┐
                                                                                 ├─▶ PixelMatch ─▶ diff.png + 8×12 영역 불일치율 + report.html/json
```

결과: `clx-src/result/visual-qa/{날짜}/{화면명}/`. 응답 요약 예 `시각 QA: 불일치 12.3% · 주요 영역 [2행/11열 60%, …] · 리포트 …/report.html`, 웹에서는 `/figma/qa/report.do?path=…`.
브라우저 탐색 순서: `figma.qa.browser` → macOS/Windows/Linux 기본 설치 경로(Chrome, Chromium, Edge) → `npx playwright`.
Chrome 은 `--screenshot` 뒤에도 헬퍼 프로세스가 남아 종료하지 않는 경우가 있어(이 PC 에서 재현), 스크린샷 파일이 생기고 크기가 안정되면 프로세스 트리를 강제 종료한다(`figma.qa.browserTimeoutSeconds`, 기본 90초).

### 3.3 검증 (`VisualQaHarness`)

pixelmatch 포팅(동일 이미지 0, 20px 이동한 120×60 상자 = 2,400 픽셀 불일치, 크기 다른 이미지 패딩), e6-compiler 헤드리스 컴파일, Chrome 153 스크린샷(1654×940, 빈 화면 비율 < 0.99 → 실제 컨트롤 렌더 확인),
`VisualQaService` 끝까지(리포트 파일 생성, Figma 없음 → 비교 생략 처리), 자기 자신과 비교 0%. 브라우저가 없는 PC 에서는 3~4번을 SKIP 하고 종료코드 0.

### 3.4 한계

- 템플릿 클래스(`btn-primary-01`, `search-box`…)의 모양은 이 프로젝트 테마에 없어(README §11) 색·여백 차이가 불일치율에 그대로 잡힌다. 기능 2 의 테마 동기화와 eXConverter-AI 테마 적용 뒤에 비교해야 수치가 의미 있다.
- 폰트: 헤드리스 렌더는 PC 에 설치된 폰트로, Figma 렌더는 Figma 폰트로 그리므로 글자 픽셀은 항상 일부 다르다. 임계값(`figma.qa.threshold`)과 영역 히트맵으로 "레이아웃 어긋남"을 보는 용도이지 0% 를 목표로 하지 않는다.
- Figma 프레임 크기와 화면 크기(EXB-FULL 1440×860)가 다르면 반응형 화면 선택이 달라진다. 뷰포트는 Figma 프레임 크기로 맞춘다.
